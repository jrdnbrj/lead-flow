## Non-blocking Cautions

### M-1 — Scope the “never Bearer” rule to Edge/API-key invocation paths

AD-12 says a Supabase secret key is never sent as `Authorization: Bearer`. That is exactly correct for `pg_net` and Edge Function invocation with new `sb_*` keys. However, the installed `@supabase/supabase-js` `2.110.9` client is officially supported for backend `createClient(url, secretKey)` and its generic REST/Auth transport may manage an Authorization fallback internally; its dedicated Functions transport is the path that explicitly suppresses a new API key as Bearer. Implementers should not build a custom Node REST transport merely to satisfy an over-broad reading of the sentence. The invariant that matters is: **new API keys must be placed only in `apikey` when invoking Edge Functions or calling through `pg_net`; user JWTs alone belong in `Authorization`.** This is a wording precision issue, not a blocker in the selected design.

### M-2 — Treat the one-minute Push boundary as an application SLO, not a Supabase scheduler SLA

Official documentation confirms sub-minute Cron scheduling, but does not promise a maximum dispatch jitter or uninterrupted invocation SLA—especially while the feature is Beta. A 20-second schedule plus a 10-second application budget is a sound design target and tolerates one missed interval, but cannot mathematically rule out consecutive platform delays. Preserve the spine's pre-enable timing test and 40/55-second alerts, record actual `scheduled_for_snapshot -> request_started_at` percentiles, and fail the pilot gate if production evidence cannot sustain NFR-004. This caution is already operationally contained by AD-9 and AD-13.

### M-3 — Pin selected Edge dependencies and watch the SSR Beta boundary

`@supabase/ssr` is still documented as Beta, despite being the recommended SSR package. The current exact installed version is valid, but Auth implementation should retain its cookie/proxy contract tests before accepting future minor updates. Likewise, `@supabase/server` or the selected Web Push library must be added with exact versions and a committed Deno lock/config; the spine already requires this before enabling Push.
