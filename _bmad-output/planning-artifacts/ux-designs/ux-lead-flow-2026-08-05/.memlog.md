- (decision) El producto conserva el shell, las rutas y componentes útiles actuales. UX incrementa jerarquía, estados y acceso a acciones; no propone reescritura ni identidad visual nueva.
- (decision) La superficie principal del asesor es un dashboard de trabajo: primero Conversaciones activas, luego Recordatorios para hoy y después Sin próxima acción. La próxima acción debe ser visible en la tarjeta cerrada.
- (decision) Captura rápida mantiene nombre, celular, interés y calificación existente; notas y próxima acción son opcionales. El cierre de captura muestra resultado y siguiente paso sin obligar a compartir el QR.
- (decision) Una respuesta entrante se representa como una única acción abierta Responder al cliente con vista previa del mensaje más reciente. Hecho manual desde WhatsApp nativo se distingue de envío verificado por Evolution.
- (decision) Push usa contexto mínimo y tres acciones Hecho, Posponer e Ignorar/No requiere respuesta. La interfaz debe distinguir generado, aceptado por servicio, suscripción inválida y acción observable; nunca afirma entrega física o lectura.
- (decision) Sincronización corporativa tiene una sola operación: vista previa, confirmación, progreso, sesión caducada, error detenido y resultado verificado con identificador externo. Reautenticar obliga a revisar y confirmar de nuevo.
- (decision) Cliente decidió comprar es un registro manual breve desde la tarjeta del lead; se comunica como fecha de registro operativo, no como inferencia del chat ni inicio del proceso posterior.
- (assumption) El asesor real preferirá resolver una acción desde una tarjeta o notificación en menos de tres interacciones y sin nota obligatoria; validar con observación en Android.
- (assumption) El vocabulario operativo comprensible es Hecho, Posponer, Ignorar/No requiere respuesta, Responder al cliente y Cliente decidió comprar; validar si Ignorar debe mostrarse como No requiere respuesta en el uso diario.
- (event) Auditoría estática completada: app actual incluye /dashboard, /nuevo, /whatsapp, /qr, shell responsive, captura por secciones, tarjeta expandible, acciones de seguimiento, Realtime, conexión WhatsApp y QR de contacto.
- (change) La implementación actual cancela acciones pendientes al recibir mensaje entrante y no expone una acción Responder al cliente; se registra como brecha de producto/estado que debe resolverse antes de desarrollo.
- (assumption) No se crean wireframes ni mocks en esta iteración porque el usuario pidió diseño UX documental, no código ni una nueva identidad visual; los contratos deben bastar para la siguiente etapa.
- (event) spines finalized: DESIGN.md y EXPERIENCE.md cubren auditoría brownfield, flujos prioritarios, estados de error, accesibilidad, responsive y decisiones a validar; no se modificó código
